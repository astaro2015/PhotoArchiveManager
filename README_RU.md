# Photo Archive Manager 1.7.1

Локальный Windows-каталог для большого семейного фотоархива. Основная цель проекта — безопасно разобрать многолетний архив: найти точные и визуальные дубли, серии, людей и события, восстановить каталоговые даты старых снимков, удобно просматривать архив по хронологии и затем при необходимости аккуратно разложить его физически.

Сборка ориентирована на Windows 10/11 x64 и публикуется как один self-contained `PhotoArchiveManager.exe`.

## Новое в 1.7.0 — человекочитаемая физическая организация архива

Физическая раскладка теперь ориентирована на то, чтобы архив оставался понятным даже без PAM:

- папки формируются как `Год → месяц/диапазон месяцев + событие` без повторного цифрового диапазона дней;
- месяцы записываются русскими сокращениями без числового префикса: `авг`, `янв-февр`, `сент-окт`;
- вручную названное событие даёт папку вроде `2016\авг — Абхазия, Пицунда`; если события нет — `2016\авг`;
- имя файла по умолчанию: `YYYY-MM-DD_исходное имя — Имена людей.ext`; **время не добавляется**;
- в имя попадают только вручную именованные/подтверждённые группы людей с актуальным индексом лиц; безымянные и автоматические группы игнорируются;
- исходное имя камеры сохраняется внутри нового имени;
- в «Организации» можно отдельно отключить дату или имена людей в целевом имени; исходное имя сохраняется всегда;
- повторная организация не дублирует дату/людей: PAM использует самое первое исходное имя из журнала `OrganizationMoves`;
- Preview и реальное выполнение используют одну и ту же функцию построения пути; правила SHA-256, запрет перезаписи и Undo не изменены;
- SQLite schema не менялась (`user_version=15`), существующую `Data/archive.db` сохранять.

Пример:

```text
Archive
└── 2016
    ├── авг — Абхазия, Пицунда
    │   ├── 2016-08-18_IMG_0133 — Маша, Олег.JPG
    │   └── 2016-08-18_IMG_0134 — Маша.JPG
    └── сент-окт — Дача
        └── 2016-09-30_DSC_0042 — Олег.JPG
```

## Исправлено и ускорено в 1.4.2 — аудит стабильности и производительности

Версия 1.4.2 сохраняет функциональность и SQLite `user_version=14`, но исправляет найденные при повторном аудите риски и уменьшает лишнюю работу на больших каталогах.

- `foreign_keys=ON` теперь гарантирован для каждого SQLite-соединения, а не только для соединения инициализации; защитные `ON DELETE CASCADE/SET NULL` больше не зависят от того, каким соединением выполняется операция;
- WAL оставлен, а `Cache=Shared` заменён на обычный cache mode, чтобы параллельные чтения не сериализовались без необходимости;
- добавлены безопасные partial/expression индексы для основных активных выборок по дате, году, источнику и камере; старую `Data\archive.db` удалять не нужно;
- общий refresh теперь перекрывает независимые read-only запросы, а первая страница библиотеки загружается параллельно со своим `COUNT(*)`;
- фильтры «Год» и «Камера» читаются параллельно;
- статистика точных дублей считается из уже загруженных групп вместо второго полного `GROUP BY`;
- добавлен ограниченный LRU-кэш декодированных миниатюр для плавной прокрутки WPF-списков без бесконтрольного роста памяти;
- `AsyncRelayCommand` теперь перехватывает и журналирует неожиданные исключения: ошибка команды больше не должна ронять WPF Dispatcher/всё приложение;
- экспорт CSV пишет потоково в файл вместо построения второй огромной строки в памяти, а подсчёт точных копий в export SQL заменён на один CTE/grouping;
- `PRAGMA optimize` выполняется после проверки/создания индексов.

Новых NuGet-зависимостей нет. Физические операции с оригиналами и правила SHA-256/Undo не изменены.

## Новое в 1.2.0 — ручная коррекция событий, иконка и встроенная справка

На вкладке **«События»** теперь можно вручную перенести один или несколько снимков из одного события в другое drag&drop:

- выберите событие слева;
- выделите один или несколько снимков в среднем списке (`Ctrl`/`Shift`);
- перетащите выделение на нужное событие слева;
- подтвердите перенос.

Операция меняет **только связи `EventFiles` в SQLite**. Файлы на диске не перемещаются, не переименовываются и не изменяются. После ручного переноса целевое событие и непустое исходное событие становятся пользовательскими/закреплёнными, чтобы следующий автоанализ не уничтожил ручную корректировку. Если исходное событие опустело, удаляется только его пустая запись из каталога PAM. Даты, GPS-центр и счётчики обоих событий пересчитываются.

- сохраняется при повторном сканировании, даже если исходный файл был изменён;
- отдельно сохраняет последнюю автоматически найденную дату сканера, поэтому ручную коррекцию можно отменить;
- обновляет `EffectiveYear`, поэтому фильтр по году сразу учитывает исправление;
- считается доверенной для событий, burst/серий и preview физической организации;
- дата Windows `fallback` по-прежнему не считается доверенной автоматически.

Если дата меняется у фотографии, которая входила в автоматическое событие, PAM отвязывает только эту фотографию от автособытия и предлагает заново запустить анализ событий. Вручную закреплённые события не разрушаются.

Для совместимости со старой `Data\archive.db` миграция выполняется на месте: добавляются поля автоматически найденной даты, существующие даты копируются в них. Удалять `Data` при обновлении не нужно.

## Сохранено из 1.0.2 — удаление группы на вкладке «Люди»

После автоматической группировки не нужно убирать лица из ненужной группы по одному. Для выбранной группы есть команда:

`Удалить / расформировать всю группу`

Она:

- одним действием отвязывает от группы все найденные лица;
- удаляет саму запись группы/имя из локального каталога PAM;
- возвращает лица в раздел `Без группы`;
- **не удаляет, не перемещает и не изменяет файлы фотографий**;
- требует явного подтверждения;
- для именованной группы отдельно предупреждает, что имя группы будет забыто.

Это пакетный аналог команды `Убрать это лицо из группы`. Если после этого снова запустить автоматическую группировку, неназванные лица могут быть сгруппированы заново.

## Сборочный фильтр OpenCvSharp analyzer

В проекте сохраняется жёсткое исключение `OpenCvSharp.Analyzers`, потому что analyzer этой версии собран более новым Roslyn и раньше создавал `CS9057`. Runtime OpenCV от этого не меняется.

## Безопасная физическая организация архива

Во вкладке **«Организация»** PAM умеет строить план физической раскладки архива.

1. Выберите отдельную корневую папку нового архива.
2. Нажмите **«ПОСТРОИТЬ PREVIEW»**.
3. PAM покажет для каждого файла `БЫЛО → СТАНЕТ` и ничего не изменит.
4. По умолчанию к перемещению отмечаются только файлы с доверенной датой: EXIF или ручной датой каталога.
5. Фото, где известна только дата файла Windows, автоматически не отмечаются.
6. В имя папки попадает только осмысленное вручную названное событие; старое служебное автоназвание, состоящее только из дат/времени, специально не добавляется.
7. Перед реальным выполнением требуется два подтверждения.
8. Каждый файл проверяется SHA-256; существующие файлы никогда не перезаписываются.
9. Между дисками применяется `copy → SHA-256 verify → delete source`.
10. Каждое успешное перемещение записывается в журнал и имеет Undo.

Пример структуры:

```text
Archive
├── 2014
│   ├── июл
│   └── авг — Отпуск в Крыму
├── 2015
│   └── ...
└── Без достоверной даты
```

При включённых настройках имени целевой файл получает календарную дату без времени и подтверждённых людей, например `2014-08-03_IMG_1234 — Маша, Олег.JPG`. Исходное имя `IMG_1234` сохраняется.

## Управление источниками

В библиотеке доступны:

- `+ Добавить папку`;
- `− Убрать источник` — сам каталог и файлы на диске не удаляются;
- `⇄ Заменить путь` — если диск/папка переехали, PAM переписывает пути своей БД и сохраняет рассчитанные анализы.

## Что уже умеет PAM

- SQLite-каталог и рекурсивное индексирование;
- EXIF, даты, камера, GPS, миниатюры;
- ручная коррекция даты только в каталоге с безопасным откатом к автоматически найденной;
- точные дубли через SHA-256;
- визуальные копии через dHash/aHash;
- Quality Score;
- безопасный карантин и Undo;
- серии/burst;
- локальное распознавание лиц YuNet + SFace;
- автоматические группы людей, ручные имена, объединение и расформирование целой группы;
- события с деревом `Год → Событие`, включая ручной drag&drop одного или нескольких фото между событиями;
- полноэкранный просмотрщик с масштабированием, навигацией и плёнкой соседних кадров;
- хронология `Год → Месяц → фото`;
- избранное и рейтинг 0–5, хранящиеся только в каталоге;
- пакетное назначение даты и события для выделенных фотографий только в каталоге;
- сохраняемые review-метки и навигация предыдущая/следующая/обработано;
- игнорирование ложной группы лиц с журналом Undo;
- экспорт метаданных каталога в JSON/CSV UTF-8;
- предварительный план физической организации архива;
- безопасные перемещения с SHA-256 и отдельным Undo.

## Критические правила безопасности

- анализ оригиналов выполняется в режиме чтения;
- ручная коррекция даты меняет только SQLite-каталог;
- никакой существующий файл не перезаписывается;
- точные дубли отправляются только в карантин после повторной SHA-256 проверки;
- визуальная похожесть сама по себе никогда не является основанием для удаления;
- окончательное удаление возможно только из карантина, после включения опасного режима и двух подтверждений;
- опасный режим сбрасывается при каждом запуске;
- автоматической очистки карантина нет;
- операции с группами людей меняют только SQLite-каталог, а не фото;
- ручные правки событий (имя, объединение, перенос фото) меняют только SQLite-каталог и закрепляют результат от автоматической перестройки.

## Сборка на «голой» Windows 10/11 x64

Распакуйте исходники и запустите:

```text
BUILD_ON_CLEAN_WINDOWS.bat
```

Скрипт сам загружает локальный .NET 8 SDK, NuGet-пакеты и необходимые модели.

Готовый EXE:

```text
BUILD_OUTPUT\PhotoArchiveManager_1.7.1_win-x64\PhotoArchiveManager.exe
```

Каталог `Data` — пользовательская база и кэш. При обновлениях его нельзя без необходимости удалять: там находятся `archive.db`, результаты анализов, лица, события, избранное/рейтинги, карантин и журналы Undo.

## Перед массовой физической раскладкой

Сначала проверяйте «Организацию» на копии небольшой папки: preview → несколько перемещений → Undo → перенос между дисками. Только после этого применять к основному архиву.
